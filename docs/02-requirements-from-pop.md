# Requirements จากป๊อป

ป๊อปคือผู้ที่ปัจจุบันเป็นคนคีย์ข้อมูลเงินสดย่อย/เงินทดรองจ่ายเข้า Odoo ด้วยมือ จึงเป็น domain expert ของ workflow ที่ระบบนี้จะเข้ามาแทนที่ ข้อกำหนดด้านล่างรวบรวมจากการพูดคุยกับป๊อปโดยตรง

## ข้อมูลที่ต้องรู้ต่อบิล

- จำนวนบิลและยอดรวมต่อเดือน (กี่บิล/กี่บาทต่อเดือน)
- ชื่อซัพพลายเออร์
- วันที่ในบิล (**Date** — ไม่ใช่ Due Date)
- รายละเอียดค่าใช้จ่าย
- ยอดรวม (Grand Total) — ใช้ทำ cross-check ว่าเอกสารที่อยู่ในมือกับรายการที่ track ตรงกันหรือไม่
- ช่องใบเสร็จสามารถเว้นว่างไว้ก่อนได้ รอเอกสารมาทีหลัง เพราะบ่อยครั้งลงข้อมูลตอนสั่งของ แล้วมากรอกส่วนที่เหลืออีกทีตอนใบเสร็จมาถึง

## Category (หมวดหมู่ค่าใช้จ่าย)

- อ่านจากเอกสารบิลเป็นหลัก
- ถ้ากำกวมให้ตีเข้าประเภทที่เป็นไปได้มากที่สุด (เช่น อุปกรณ์ทำความสะอาด → EXP)

## Vendor (ซัพพลายเออร์)

- ซัพพลายเออร์ที่สั่งประจำมี list อยู่แล้ว
- เจ้าใหม่ที่ยังไม่เคยมีในระบบ ต้องสร้าง contact ใหม่

## Cost Center

- ตัวอย่างจริงจากการใช้งาน: `TD050100` (General Management Admin)

## Acc name (ชื่อบัญชี)

- ตัวอย่าง: "สิ้นเปลืองใช้ไฟ"
- สามารถตั้งค่า mapping ล่วงหน้าได้

## วันที่ (Date)

- ใช้ **วันที่ในบิลเท่านั้น** ห้ามใช้ Due Date

## ประเภทของใบเสร็จ

- ใบเสร็จรับเงิน
- ใบกำกับภาษี
- บิลเงินสด

## กรณีบิลไม่สมบูรณ์

เช่น ใบเสร็จจากร้าน 7-Eleven ที่ไม่มีใบเสร็จแบบเป็นทางการ — ระบบต้องมี popup เสนอสร้าง **"เอกสารรับเงิน"** จาก template ของบริษัท โดยระบบมีหน้าที่แค่เติมข้อมูลให้ครบ ได้แก่:

- ชื่อผู้รับเงิน / เลขบัตรประชาชน
- ได้รับเงินจากค่าอะไร
- จำนวนเงิน ทั้งเป็นตัวเลขและตัวหนังสือ
- ช่องรับรองถูกต้อง ใส่ชื่อผู้รับเงิน

## จำนวนเงิน

- แยกเป็น 3 ค่า: ก่อน VAT / VAT 7% / หลัง VAT (Grand Total)

## การเลือกประเภทเงินก่อน submit

- ก่อน submit ต้องเลือกว่าบิลนี้เป็น **Advance (สำรองจ่าย)** หรือ **Petty Cash**

## กติกาอัตโนมัติสำหรับจำแนกประเภทเงิน

- บิล **฿20,000 แรกของเดือน** (นับสะสม ไม่เรียงตามวันที่) = Petty Cash
- หลังจากนั้น = Advance

> **ขอบเขตที่ยังไม่ชัด**: ถ้าบิลใบหนึ่งมียอดคาบเกี่ยวจุดตัด ฿20,000 พอดี ควรตัดทั้งใบเป็นประเภทเดียว หรือแบ่งสัดส่วนตามยอดที่คาบเกี่ยว — ยังไม่มีคำตอบ ต้องถามป๊อปเพิ่มเติม (ดู [docs/04-open-items.md](./04-open-items.md))

## หมวดหมู่ต้องอิง Odoo จริง

- หมวดหมู่ทั้งหมดต้องล้อตามหัวข้อจริงใน Odoo เท่านั้น ห้ามตั้งขึ้นเอง

## การแนบไฟล์

- แนบไฟล์ PDF / JPEG / PNG แล้วอัปโหลดเข้า Google Drive อัตโนมัติ
- ตั้งชื่อไฟล์ตามชื่อ Vendor (ทั้งภาษาไทยและอังกฤษ)
- แยกโฟลเดอร์ตามเดือน

## เลขที่เอกสาร

- ต้องมีเลขที่เอกสาร
- ต้องมีเลขที่ใบสั่งซื้อ (PO) ถ้ามี

## การเชื่อมต่อ Odoo (เฟสนี้)

- มีช่องกรอก ID Odoo (ID Express) แบบกรอกมือ เนื่องจากการเชื่อมต่อ Odoo จริงยังไม่ทำในเฟสนี้

## การแจ้งเตือนรายการซ้ำ

- ตรวจจากชื่อบริษัท + จำนวนเงิน + วันที่เอกสารที่ซ้ำกัน
- แสดงเป็น popup ตอนกด submit
- ให้ขึ้นแถวสีแดงเพื่อให้ผู้ใช้ cross-check ก่อนยืนยัน

## คุณค่าที่ป๊อปคาดหวังจากระบบ

- ลดเวลาทำงานในส่วนนี้
- ลดการกรอกข้อมูลซ้ำซ้อน
- มีรูปภาพและเอกสารหลักฐานที่ชัดเจน ค้นหาย้อนหลังได้ง่าย

## ผลกระทบของปัญหาเดิม (สาเหตุที่ต้องทำโปรเจกต์นี้)

- ใช้เวลามากเกินความจำเป็นในการบันทึกค่าใช้จ่ายแต่ละครั้ง
- กรอกข้อมูลซ้ำซ้อน 2 รอบ (ทั้งใน Google Sheet และใน Odoo)
- ขั้นตอนลงรูปหลายทอด (ถ่ายรูป → ส่งเข้า Slack → เปิดคอมพิวเตอร์ → แนบเข้า Odoo)
